# v5-pixel-temporal — in-flight viz strips

Generated by `scripts/sr_temporal_inflight_viz.py` running every 5 minutes against the latest checkpoint of the v5-pixel-temporal warm-start training run on `<train-host>`. Each strip is a six-panel compositor:

```
LR-bilinear  |  bicubic  |  v5-pixel-temporal  |  GT  |  |error|
```

(The fourth and fifth panels are merged in this build because the v4-baseline column was removed once we recognised v4-on-TartanAir is rainbow chromatic dispersion — meaningful only as the "where we started" anchor, not a comparison reference.)

## Files

| File | Step | Notes |
|---|---|---|
| `step-00042000.jpg` | 42,000 / 80,000 (~52% of warm-start training) | Phase 2 (joint backbone fine-tune); LR-synth via `EngineAliasedLRSynth`. JPEG quality 85, half spatial resolution of the original 3840×1920 PNG (~10 MB) for repo-friendly inline embedding. |

## How to read these images

- The **OSS column should approach the GT column visually** as training progresses. Mid-flight, expect partial recovery — fine high-frequency detail (hair, distant edges, thin features) trails low-frequency content (lighting, gross shapes).
- The **|error| column** is a luminance heatmap of `|OSS − GT|`, with brighter = larger error. Bright concentrations near thin features are the published failure mode of pixel-grid SR (Nyquist-bounded; see RESEARCH.md §7 Limitations); v6 covariance resampling is the architectural fix scheduled for the next round.
- The **bicubic column** is the cheap baseline. OSS must clearly beat bicubic perceptually (visual sharpness, less blur on edges) — that's the floor below which the model would not be worth shipping.

## Caveat for the academic reader

These are **in-flight illustrations from a partially-trained model**, not final measurements. They show that the architecture is producing coherent output and converging in the expected direction; they are **not** evidence that v5-pixel-temporal beats DLSS, FSR, or any other system. Apples-to-apples vendor comparisons require the DLL-shim infrastructure (Sprint 7) running both systems on identical content; that is unbuilt as of writing. See `docs/results/README.md` for the planned gallery layout once that infrastructure exists.

## Regeneration

To regenerate after a new checkpoint:

```bash
scp <train-host>:<train-host-data>/checkpoints/srcnn-v5-pixel-temporal/viz/step-NNNNN.png \
    docs/results/v5-pixel-temporal/in-flight/

python -c "
from PIL import Image
img = Image.open('docs/results/v5-pixel-temporal/in-flight/step-NNNNN.png')
new = img.resize((img.size[0]//2, img.size[1]//2), Image.LANCZOS)
new.convert('RGB').save(
    'docs/results/v5-pixel-temporal/in-flight/step-NNNNN.jpg',
    quality=85, optimize=True
)
"

rm docs/results/v5-pixel-temporal/in-flight/step-NNNNN.png
```
