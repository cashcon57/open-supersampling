# OSS v6.2 Architecture v4 Specification

**Status:** Committed 2026-05-08 (signed off by Cash)
**Supersedes:** v6.1 architecture (HAT-Tiny + dense cross-attn + 64-channel raster + dense spawner)
**Companion:** `docs/research/2026-05-08-phase4-priority-stack-v4.md`

---

## 1. Product positioning

OSS is a **vendor-neutral, hardware-tiered, SR+FG-unified upscaler**. Same architecture across 5 hardware tiers from RTX 5090 down to Steam Deck / integrated graphics via shader-only fallback.

**Reference targets:**
- **3080 Ti desktop** (training rig): mid-high tier, R=8, ~3-5ms SR+FG
- **4070 mobile** (dev rig): mid-high tier, R=8, ~5-6ms SR+FG (bandwidth-constrained)

**Shipping order:** NVIDIA-first (CUDA + TensorRT), with **vendor-specific kernels for AMD (HIP/ROCm), Intel (oneAPI), Apple (Metal)** following — Path C from 2026-05-08 strategy decision. **No-ML shader variant ships alongside v6.2** (Slang/Vulkan compute), not deferred.

---

## 2. Architectural philosophy

> **The Gaussian canvas is an L2-friendly temporal residual cache layered on top of reprojection. The neural network corrects only where the canvas+reprojection fails. Frame-gen is a deterministic byproduct of canvas advection.**

This is the differentiator. Not "neural Gaussian renderer." Not "DLSS competitor with Gaussians." Specifically: **explicit advectable geometric cache**, so the network doesn't have to be DLSS-sized.

## 3. Pipeline

### 3.1 Persistent inference state

```
Per-Gaussian (FP16 packed, ~24 bytes minimum):
  xy:         FP16×2  (4 bytes)
  conic Λ:    FP16×3  (6 bytes)  — persists; scale/rot training-only
  rgb:        FP16×3  (6 bytes)  — direct color (R=4 mode) or low-rank z (R=8 mode)
  confidence: FP16    (2 bytes)
  age:        UINT8   (1 byte)
  cov_id:     UINT8   (1 byte)   — optional, codebook index for LUT path
  [pad to 24 bytes]

16k Gaussians × 24 bytes = 384 KB → fits L2 on all reference targets
```

Training graph keeps `(scale, rot, feat_64)` for differentiability; inference graph drops these and persists conic Λ + low-rank `z` directly.

### 3.2 Hot path (per displayed source frame)

```
1. Preprocess + validity mask  (fused compute pass)
   inputs:  LR color, motion vectors, depth, optional g-buffer
   outputs: packed residual, 1-bit validity mask per 16×16 tile, disocclusion bitmap

2. HR reprojection
   for each HR pixel p:
     p' = p − u_t(p)
     V(p) = depth_consistent(p, p') ∧ motion_smooth(p) ∧ material_match(p, p')
     I_base(p) = I_{t-1}^HR(p')  if V(p)=1  else  fallback

3. Canvas warp (Jacobian-free for ~90% of canvas)
   for each Gaussian g:
     μ_g' = μ_g + u(μ_g) Δt
     if |∇·u(μ_g)| < ε:  Λ_g' = Λ_g (translation-only)
     else:               Λ_g' = A^-T Λ_g A^-1  with A = I + Δt ∇u
     confidence_g' = confidence_g · exp(-λ_age Δt) · (1 - disocclusion_at_μ_g')

4. Tile rebin (incremental, persistent lists)
   for each Gaussian g whose AABB tile-range changed:
     remove from old tiles, insert into new tiles (counting sort)
   most Gaussians: tile-range unchanged → skip

5. Sparse low-rank Gaussian raster (R=8, conic row recurrence, 2×2 register tiling)
   only on tiles where validity_mask = 0 OR residual_priority > τ
   for each tile:
     Z(p) = Σ_g w_g(p) z_g  / (ε + Σ_g w_g(p))
     m(p) = Σ_g w_g(p)
   row-recurrence inside inner loop:
     w_{x+1} = w_x · r_x ;  r_{x+1} = r_x · exp(-a)

6. Concat-fusion + 1×1 conv decode  (Quality tier baseline)
   F'(p) = F(p) + ψ_θ([F(p), Z(p), m(p), I_base(p), depth(p), MV(p)])
   ψ_θ = 1×1 → depthwise 3×3 → 1×1, INT8 if available

7. Optional sparse student backbone  (active tiles only, 30Hz amortized)
   ~1M params (verify via HAT-Tiny measurement first), TensorRT INT8 for NVIDIA
   inputs: F'(p) on active tiles
   outputs: refined feature delta

8. Optional local top-K attention  (Quality+ tier, disocclusion tiles only ~5% of windows)
   K=16, head_dim=32 (padded), 1-head, batched single SDPA call

9. Composite + tonemap → swapchain
   I_t^HR(p) = I_base(p) + ΔI(p)
   fused fragment shader; DX12/Vulkan interop, no readback
```

### 3.3 Hot path (per generated frame, FG mode only)

```
1. Late frame reprojection at +α·Δt
2. Canvas extrapolation (second warp pass)
3. Hole/edge correction only (validity mask drives sparse raster)
4. Composite

I_{t+α}^HR(p) = I_t^HR(p − α·u_t(p)) + M_hole · ΔI_gauss
```

No HAT, no cross-attn, no spawner on generated frames.

### 3.4 Async / amortized (off display path)

- **Spawner** (disocclusion-only birth): runs at 30Hz on tiles flagged by disocclusion mask. Hard-spawn at exact disoccluded pixel center, velocity = motion vector at that pixel, covariance = DGP softmax over 8-16 prototype Σ. Cap births: 256/frame, 1-4/tile.
- **Kalman maintenance** (existing Gaussians): 6-FLOP per Gaussian update, runs every frame on rebin step.
- **HAT-Tiny TEACHER** (training only): used for distillation supervision. Not in inference path.
- **Tile rebalance**: full rebin only on scene cuts or large camera jumps; incremental otherwise.

## 5. Vendor-specific kernel plan (Path C)

Architecture stays cross-vendor at semantic level. Each vendor gets specialized kernels for hot paths after baseline ships.

| Vendor | Primary runtime | Specialized kernels |
|--------|----------------|---------------------|
| **NVIDIA** | CUDA + TensorRT | wmma/mma.sync raster, cooperative-groups warp-reduce, cp.async pipeline |
| **AMD** | HIP/ROCm | RDNA3 wave64 matrix-cores, LDS-resident canvas, async DMA |
| **Intel** | oneAPI / DPC++ | XMX matrix engines, Xe-cores, ESIMD for predicated raster |
| **Apple** | Metal MPS / Performance Shaders | Tensor cores on M3/M4, Metal compute heaps, persistent threadgroup memory |
| **Cross-vendor fallback** | Slang → Vulkan compute | Universal compute-shader path, no-ML variant |

NVIDIA ships first (v6.2). AMD/Intel/Apple kernels scheduled v6.2.1 / v6.2.2 / v6.2.3 (separate releases).

## 6. v6.2-pico-002 training spec

Killing v6.1-pico-001 (currently training, stippling artifact unfixed). Clean restart with v4 architecture.

**Training config:**
- Architecture: full v4 above (R=8 latent, concat-fusion, disocclusion spawner, Kalman maintenance)
- HAT-Tiny: TEACHER role only (distillation supervision); NOT in inference graph
- Student: distillation in v6.2.1 (after HAT-Tiny ms measurement gates the size decision)
- Canvas capacity: 16k (mid-high reference)
- Loss: L1 + 0.1·LPIPS + 0.05·distillation (HAT feature L1)
- Schedule: 50k step warm-up @ R=4 RGB-direct, then enable R=8 latent + decoder

**Acceptance gates:**
- PSNR within 0.3dB of v6.1-pico-001 best checkpoint
- LPIPS within 0.02
- **Stippling artifact gone** (FFT residual λ=2px peak < 50K, vs current 177K)
- Forward time on 3080 Ti at 1080p output: <5ms (Quality+FG mode)

If gates miss, debug pipeline does not block release of pre-validated Tier 0+1 changes.

## 7. Risk register

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| HAT-Tiny actual ms is ~1ms not 2-3ms (Opus arithmetic wrong) | High | Measurement codex job queued; if confirmed, keep HAT in inference path async-30Hz instead of distilling to ≤1M |
| L2 residency doesn't materialize in shipping engine context | Medium | Treat as design target, not guarantee. Validate via Nsight in real game integration. |
| 4070 mobile bandwidth-constrains R=8 → forces R=4 | Medium | Ablate R=4 vs R=8 on 4070 mobile target during pico-002 training |
| Disocclusion spawner alone doesn't kill stippling | Medium | Compound with DGP dictionary + blue-noise jitter (three-layer defense) |
| Frame-gen 2nd pass is more expensive than estimated | Medium | Measure on pico-002; if >2.5ms, gate FG behind Quality+ tier only |
| Vendor-specific kernels lag (AMD/Intel/Apple) | High | Cross-vendor Slang/Vulkan baseline ships in v6.2; vendor optimizations are v6.2.x sequence |
| Council's "≤0.4M student" too aggressive, quality drops | High | Bound student size by quality gate (PSNR within 0.3dB of HAT teacher); allow up to ~5M if needed |

## 8. Open questions (require empirical validation)

1. **HAT-Tiny actual ms on 3080 Ti and 4070 mobile at FP16 TC** → gates student size
2. **R=4 vs R=8 quality delta at fixed canvas density** → gates Mid-high default
3. **Counting-sort tile bin actual μs at N=16k** → gates Tier 1e
4. **Disocclusion-only spawner alone vs +DGP vs +DGP+blue-noise** → which combination kills stippling cheapest
5. **Frame-gen 2nd pass actual ms** → if >2ms, what shares poorly?
6. **L2 residency hit rate during real engine integration** → directional design vs quantitative guarantee

These get codex measurement jobs queued in priority order.

## 9. Out of scope for v6.2

Deferred to v8 / future:
- 8-tier dynamic degradation governor
- Mode A "1ms competitive" SR-only product preset
- TC-GS W·G matmul kernel rewrite (do AFTER baseline measures)
- LUT covariance codebook per-Gaussian (do AFTER conic recurrence measures show transcendentals are still bottleneck)
- Adaptive canvas capacity (`S = √(residual·motion entropy)`)
- Multi-rate per-stage scheduling (raster 120Hz / backbone 60Hz / cross-attn 30Hz)
- Hierarchical two-level rasterizer (coarse H/4 + refinement)
- Multi-frame gen 4× (Halo tier toggle later)
- Speculative frame extrapolation with rollback
