# v6.2-pico-light ablation spec

**Operator decision:** 2026-05-08
**Status:** planning spec; starts only after `srcnn-v6.1-pico-001` validates
cross-engine at step ~30K-50K
**Goal:** run parallel ablations to find the Pareto-optimal smaller v6.2
pico-light backbone.
**Primary hardware:** RTX 3080 Ti

## TL;DR

Run three post-v6.1 ablations against the same held-out gates:

1. `srcnn-v6.2-pico-light-distilled-001` - 1M-3M student backbone, target
   2M, distilled from the existing v6.1 HAT-Tiny teacher.
2. `srcnn-v6.2-pico-light-fromscratch-001` - 2M backbone trained directly
   with the full post-2026-05-08 v6 loss mix.
3. `srcnn-v6.2-pico-light-f32-001` - same backbone family as from-scratch,
   but with `F=32` channels instead of the v6.1 `F=64` feature vector.

The winner is not the highest-PSNR model by default. Pick the Pareto winner by
held-out PSNR, held-out LPIPS, and measured 1080p to 4K wallclock on RTX 3080
Ti. All candidates must beat v4 on TartanAir, UE5, and Unity held-out sets.

## Launch gate

Do not start v6.2-pico-light runs until `srcnn-v6.1-pico-001` has validated
cross-engine quality at step ~30K-50K. The preferred teacher checkpoint for
distillation and warm-start is the stable v6.1 checkpoint around step ~100K.

Blocking conditions:

- v6.1 must beat v4 on TartanAir, UE5, and Unity held-out sets.
- v6.1 must have a stable checkpoint selected for teacher inference and
  component warm-start.
- The post-2026-05-08 retuned v6 loss lambdas must be locked for this ablation
  round before from-scratch and F=32 training starts.

## Shared setup

All variants keep the v6 scaffold constant unless the variant says otherwise:

- Canvas, spawner, pixel-Gaussian cross-attention, and composite head are
  warm-started from `srcnn-v6.1-pico-001` around step ~100K.
- The candidate backbone starts fresh unless a Net2Net transfer path is
  explicitly selected for that architecture.
- Dataset mix, crop policy, trajectory length, augmentation, checkpoint cadence,
  and eval scripts should match the validated v6.1 recipe.
- Output run names are fixed and must be registered in dashboard/run allow-list
  only after the runs exist.

## Backbone candidates

| Candidate | Approx params | Notes |
|---|---:|---|
| HAT-Pico custom | ~1.5M | Slim transformer option; closest to v6.1 HAT-Tiny inductive bias. |
| NAFNet-2M | ~2.0M | Strong lightweight restoration baseline; good candidate for direct v6 losses. |
| EDSR-baseline-lite | ~1.5M | Simple residual SR baseline; lowest implementation risk. |
| ResBlock stack | ~3.0M | Conservative CNN option if 1.5M-2M underfits; still materially smaller than v6.1. |

Primary target for v6.2-pico-light is ~2M parameters. Treat 1M-3M as the
allowed range; anything above 3M needs a separate approval because it erodes the
latency target.

## Variant A - distilled backbone

**Run:** `srcnn-v6.2-pico-light-distilled-001`

Purpose: compress the existing v6.1 HAT-Tiny backbone into a 1M-3M student
while preserving teacher behavior.

Teacher:

- Frozen `srcnn-v6.1-pico-001` with existing HAT-Tiny backbone, approximately
  9M parameters.
- Use the stable checkpoint around step ~100K if it remains the selected v6.1
  checkpoint after cross-engine validation.

Student:

- Target size: 2M parameters; allowed range 1M-3M.
- Architecture options: ResBlock stack or slimmed transformer.
- Preferred first pass: HAT-Pico custom or NAFNet-2M if their feature taps can
  cleanly align with HAT block outputs.

Warm-start:

- Warm-start canvas, spawner, cross-attention, and composite head from v6.1.
- Initialize only the student backbone from scratch.
- If feature dimensions differ, use learned 1x1 adapters for distillation taps
  rather than mutating the warm-started v6 components.

Loss:

```text
L_distill =
    sum_blocks MSE(student_features_at_each_HAT_block_output, teacher_features)
  + lambda_out * MSE(student_final_output, teacher_final_output)
  + lambda_v6 * L_v6_post_retune(student_final_output, ground_truth)
```

`L_v6_post_retune` is the existing v6 perceptual and pixel mix after the
2026-05-08 retune: Charbonnier, LPIPS, multi-scale VGG, wavelet, Sobel,
temporal consistency, and gated GAN terms as applicable to the active v6
recipe.

Schedule:

- Setup: ~1 day to add feature taps/adapters and teacher target plumbing.
- Training: 50K-100K steps, about 1 week on RTX 3080 Ti.
- Phase 1, 0-5K: freeze warm-started non-backbone modules; train student
  backbone and adapters against teacher features/output.
- Phase 2, 5K-50K: unfreeze full model at low LR for warm-started modules and
  normal LR for the student backbone.
- Phase 3, 50K-100K: continue only if held-out PSNR/LPIPS is still improving or
  latency/quality tradeoff is promising.

Failure mode:

- The student may overfit teacher artifacts and inherit v6.1 mistakes instead
  of improving against ground truth. Detect this by comparing teacher-match
  metrics against GT PSNR/LPIPS and by inspecting failure cases where teacher
  and student both lose to v4 or v5.

## Variant B - from-scratch smaller backbone

**Run:** `srcnn-v6.2-pico-light-fromscratch-001`

Purpose: test whether a 2M-class backbone trained directly with the retuned v6
objective beats teacher imitation at the same latency target.

Architecture:

- 2M-param ResBlock stack or EDSR-baseline-style network.
- Skip the teacher entirely; no feature or output distillation loss.
- Preferred first pass: NAFNet-2M or EDSR-baseline-lite, whichever fits the
  existing v6 feature interface with less adapter code.

Warm-start:

- Same as Variant A: warm-start canvas, spawner, cross-attention, and composite
  head from v6.1.
- The smaller backbone starts from scratch.

Loss:

- Full v6 loss mix using the post-2026-05-08 retuned lambdas.
- No teacher target term.

Schedule:

- Setup: ~1 day to wire the candidate backbone into the v6 trainer.
- Training: 50K-100K steps, about 1 week on RTX 3080 Ti.
- Phase 1, 0-5K: freeze warm-started non-backbone modules so the fresh backbone
  learns to feed the existing v6 scaffold.
- Phase 2, 5K-50K: unfreeze full model; use a lower LR multiplier for
  warm-started modules.
- Phase 3, 50K-100K: continue if cross-engine held-out quality has not
  plateaued.

Failure mode:

- The smaller backbone may underperform the v6.1 teacher because it never sees
  teacher intermediate structure. Escalate to the 3M ResBlock option or the
  distilled variant if PSNR and LPIPS lag while training loss still improves.

## Variant C - F=32 channel ablation

**Run:** `srcnn-v6.2-pico-light-f32-001`

Purpose: measure whether halving the v6 feature-vector width gives enough
latency savings to justify the quality risk.

Architecture:

- Same backbone family as Variant B.
- `F=32` feature channels instead of the v6.1 `F=64` default.
- No teacher distillation.

Expected performance impact:

- Rasterizer and composite head should see near-linear savings from lower
  feature width.
- Target runtime is ~3ms at 1080p to 4K on RTX 3080 Ti if the 2M/F=64 variants
  land near ~5ms.
- Main risk is about 5% quality loss from reduced feature-vector expressiveness.

Warm-start:

- Backbone starts from scratch.
- Warm-start compatible components from v6.1 where tensor shapes match.
- For `F=64` to `F=32` shape changes, use explicit projection, partial-copy, or
  reinitialize only the incompatible feature-width layers. Record which path was
  used in the run notes before training starts.

Schedule:

- Setup: ~1 day after Variant B wiring exists.
- Training: 50K-100K steps, about 1 week on RTX 3080 Ti.
- Prefer running in parallel with Variant B once the shared backbone interface
  is stable.

Failure mode:

- F=32 may be latency-optimal but visibly lose fine texture, subpixel edge
  stability, or temporal consistency. Reject it if the quality loss exceeds the
  latency value, even if PSNR stays within estimate.

## Net2Net warm-start vs cold start

| Path | Applies to | Use when | Risk |
|---|---|---|---|
| v6 scaffold warm-start | All variants | Default path: reuse canvas, spawner, cross-attention, composite head from v6.1. | Shape drift can silently invalidate copied weights; log copied and reinitialized modules. |
| Backbone cold start | All variants by default | Candidate backbone differs from v6.1 HAT-Tiny or has lower capacity. | 0-5K steps may be unstable while fresh backbone learns the warm-started interface. |
| Net2Net backbone transfer | Optional for HAT-Pico custom | Student is a clean width/depth shrink of the v6.1 HAT-Tiny backbone. | Can bias the ablation toward teacher behavior and confound from-scratch comparison. |
| Full cold start | Fallback only | Warm-started scaffold causes instability or incompatible tensor contracts. | Costs more wallclock and weakens comparability to v6.1. |

Default decision: warm-start the v6 scaffold and cold-start the backbone. Use
Net2Net only as a logged sub-ablation if the HAT-Pico custom path is selected
and the transfer is mechanically clean.

## Held-out eval and Pareto selection

Primary metrics:

- PSNR against GT HR.
- LPIPS against GT HR.
- Wallclock on RTX 3080 Ti for 1080p to 4K inference.

Cross-engine gate:

- Evaluate both primary v6.2 variants and the F=32 ablation on TartanAir, UE5,
  and Unity held-out sets.
- Every v6.2-pico-light candidate must beat v4 on all three engines before it
  can be considered a winner.
- If a candidate beats v4 on aggregate but fails one engine, keep it as a
  diagnostic run, not the selected pico-light model.

Tie-breakers:

1. Reject any candidate that fails the cross-engine v4 gate.
2. Prefer lower LPIPS if PSNR differs by less than 0.1 dB.
3. Prefer lower wallclock if PSNR differs by less than 0.15 dB and LPIPS is
   statistically tied.
4. Prefer the simpler architecture if metrics and runtime are tied, because it
   lowers deployment and kernel-port risk.

Dashboard reporting:

- Plot all four rows in the Pareto chart: v6.1 control, distilled,
  from-scratch, and F=32.
- Report measured wallclock with the exact checkpoint, resolution, GPU, driver,
  CUDA/PyTorch version, and whether custom CUDA kernels were enabled.
- Mark estimated values as estimates until replaced by measured data.
