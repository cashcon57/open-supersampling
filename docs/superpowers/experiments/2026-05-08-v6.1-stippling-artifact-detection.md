# 2026-05-08 — v6.1-pico-001 stippling artifact detected

## Status

Operator (Cash) noticed visual stippled / dotted pattern in v6.1 output similar
to what killed v6.0. Confirmed via visual inspection + FFT residual analysis at
step 11,000. Root cause narrowed to per-pixel checkerboard (λ=2px), not the
16-pixel grid that hit v6.0.

## Method

1. Pulled viz strips at steps 4000, 6000, 8000, 10000, 11000.
2. Cropped the v6.1 model-output column (column 3 of 7) and GT column (col 4).
3. Visual-inspected the foliage region (high-frequency, exposes artifacts).
4. Computed FFT of the residual `v6.1 − GT` to find frequencies present in v6.1
   but absent in GT.

## Findings

**Visual:** v6.1 output shows a regular dotted / mosaic pattern across the
entire image. Most visible on dark walls + foliage shadows + smooth surfaces.
GT is clean. Evidence images at:
- `v61-step11000-stippling-evidence.png` (3× zoom, foliage region)
- `gt-step11000-clean-reference.png` (same region, GT, clean)
- `v61-residual-fft-evidence.png` (residual visualization)

**Quantitative — top FFT peaks of residual (v6.1 - GT):**

| Rank | λx (px) | λy (px) | Magnitude | Interpretation |
|---|---:|---:|---:|---|
| 1 | **2** | ∞ | 177,265 | **horizontal checkerboard** (per-pixel) |
| 2 | ∞ | **2** | 138,551 | **vertical checkerboard** |
| 3-9 | 213 / 128 | 5-6 | ~50K each | low-freq building features (also in GT, harmless) |
| 10 | ∞ | 28.24 | 53,792 | possible spawner-tile period — investigate |

The residual mean-abs error is 9.09/255 (~3.6%) which matches earlier finding
of ~9/255 mean(|v6.1-GT|) at step 7500, and the model is now drifted slightly
worse vs early-training (step 1000 minimum was 8.3/255).

**Trend across steps:** the residual FFT peaks at λ=2px are stable across
steps 4000-11000. The artifact was present early and has not been suppressed
by training. This rules out "transient training noise" — it's a structural
issue.

## Comparison vs v6.0

v6.0 had a documented 16-pixel grid artifact (per memory note: "v6.1 fixes vs
v6: randomized per-frame spawner tile offsets + overlapping rasterizer tiles
with cosine feathering"). The randomization + overlap fixed the 16-px-period
artifact specifically.

v6.1's stippling is at **2-pixel period**, not 16-pixel. Same class (regular
spatial-frequency leakage) but a different mechanism. The 16-pixel fix was
correct but didn't address sub-tile aliasing.

## Hypothesized causes (priority-ordered)

### H1 — Transposed convolution in the composite head (most likely)

The classic Odena et al. (2016) "Deconvolution and Checkerboard Artifacts"
finding: transposed convolutions with stride > 1 produce checkerboard
artifacts whose period equals the stride. If the composite head or any
upscaling layer in v6.1 uses `nn.ConvTranspose2d(stride=2)`, that's the smoking
gun.

**Standard fix:** replace transposed-conv with `nn.Upsample(scale_factor=2, mode='nearest')` (or 'bilinear') followed by `nn.Conv2d(stride=1)`. Eliminates checkerboard by construction.

Action: audit `oss/sr/v6/model.py` for any `ConvTranspose2d` or `PixelShuffle`
with even stride. Per the v6 design memo, suspects:
- The composite head (whatever projects rasterizer output → 3-channel RGB)
- Any upsampling block before the final composite

### H2 — Gaussian rasterizer sub-pixel aliasing

The 2D Gaussian rasterizer evaluates `exp(-0.5 * Q)` per pixel center, with
Gaussians centered at sub-pixel positions. Two adjacent pixels see the same
Gaussian's contribution at slightly different distances → values differ. If
the model's spawner places Gaussians on integer pixel centers (or near them)
with regularity, the per-pixel weight pattern produces a 2-pixel
high-frequency oscillation.

**Test:** check if `xy` outputs from the spawner are biased toward
integer-pixel positions. Compute `xy.frac().mean(dim=0)` from a saved ckpt;
if mean fractional part is near 0 or near 0.5, that's a bias.

**Standard fix:** add a sub-pixel jitter to spawned `xy` during training so
the model learns to be location-independent.

### H3 — Even-stride bilinear upsampling

Less likely than H1 but possible. If the model uses `F.interpolate(..., scale_factor=2, mode='bilinear', align_corners=False)`, the alignment can produce a 2-pixel artifact.

### H4 — Per-pixel weight normalization with rounding

The rasterizer's `topk_norm=True` divides by per-pixel weight sum (though we
saw earlier the reference path actually ignores this — confirm). If the
divisor is computed differently for even-vs-odd pixels (e.g., due to a
quantization or rounding), that produces 2-pixel-period output.

## Recommended next steps

1. **Audit the model architecture** for transposed-conv or pixel-shuffle in

2. **Sub-pixel jitter probe** on a saved ckpt — read `xy` outputs from the

3. **Replace any ConvTranspose2d with upsample+conv** if found. Retrain a

on training crops doesn't capture the stippling penalty (PSNR averages over

HAS been moving — but the floor is set by this artifact.
