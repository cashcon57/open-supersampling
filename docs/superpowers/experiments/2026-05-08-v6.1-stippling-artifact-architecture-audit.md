# 2026-05-08 — v6.1 stippling artifact architecture audit

## Verdict

The v6.1 generator does not contain the H1 smoking gun. I found no active
`nn.ConvTranspose2d`, `nn.PixelShuffle`, `F.conv_transpose2d`, or
`F.interpolate(..., mode="nearest", scale_factor=2)` in `oss/sr/v6`.

The 2px FFT peaks are still a real checkerboard-class artifact, but the likely
mechanism is not Odena-style transposed-convolution overlap. The first opt-in
fix to test is H2: add continuous sub-pixel jitter to spawned Gaussian centers
during training so the rasterizer cannot learn an integer/parity-locked center
distribution.

## Spawner XY path

The active spawner is `oss/sr/v6/gaussian_spawner.py`; there is no
`oss/sr/v6/spawner.py`.

`GaussianSpawner._tile_centers` builds HR centers from integer aranges:
`(tile + 0.5) * tile_size_hr` at `oss/sr/v6/gaussian_spawner.py:219`.
For v6.1 defaults this initializes centers at `8, 24, 40, ...`, exactly integer
HR pixels. The learned offset is continuous:
`positions = centers_b + torch.tanh(offset_raw) * offset_bound` at
`oss/sr/v6/gaussian_spawner.py:194`, with no `.round()`, `.floor()`, or `.long()`
applied to `xy` after decoding.

Existing `spawn_offset_random=True` adds a cached integer HR-pixel tile offset
in `V6Model._spawn_offset_for`; it randomizes the 16px tile phase but keeps the
fractional part at zero. That fits the memo: v6.1 can fix the 16px grid while
leaving a 2px/per-pixel parity leak.

Remote checkpoint probe on `3080ti-windows` read
`E:\checkpoints\srcnn-v6.1-pico-001\step-00011500.pt` at step 11500. The
spawner is continuous, but the full path still showed fractional-position

## Rasterizer normalization

`V6Rasterizer` constructs `Rasterizer(tile_size=tile_size)` without overriding
`topk_norm`, so the CUDA/OSS CUDA production path uses
`Rasterizer(topk_norm=True)` by default. The flag is passed to the OSS CUDA path
at `oss/gaussian/renderer/rasterizer.py:186` and the vendored CUDA path at
`oss/gaussian/renderer/rasterizer.py:238`.

The PyTorch reference fallback ignores `topk_norm`; `_render_reference` directly
accumulates `weight * feat` at `oss/gaussian/renderer/rasterizer.py:292`.
The v6 overlap wrapper has a separate four-phase feather normalization at
`oss/sr/v6/rasterizer.py:162`, but that normalization is tile-phase smoothing,
not per-Gaussian top-K normalization.

## First fix to test

Implemented an opt-in H2 ablation:

- `V6Config.spawn_subpixel_jitter` in `oss/sr/v6/model.py:117`
- `V6Model._spawn_offset_for` adds a cached uniform `[0, 1)` HR-pixel offset
  when enabled at `oss/sr/v6/model.py:558`
- trainer flag `--spawn-subpixel-jitter` in `scripts/sr_train_v6.py`

Launch v6.1-pico-002 with the existing v6.1 grid fixes plus the new jitter:

```bash
python scripts/sr_train_v6.py \
  --output-dir E:\checkpoints\srcnn-v6.1-pico-002 \
  --spawn-offset-random \
  --spawn-subpixel-jitter \
  --rasterizer-overlap 8
```

Parameter delta: 0. This is a training-time coordinate augmentation, not a new
module. Existing v6.1 weights load unchanged because no state-dict keys change,
but the recommended experiment remains a fresh v6.1-pico-002 run rather than a
mid-flight mutation of v6.1-pico-001.
